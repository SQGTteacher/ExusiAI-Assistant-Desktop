# ClassIsland 生命周期验证

`ExusiAI.Desktop.exe --verify-classisland <输出目录>` 在真实 Windows WPF 进程中验证打包后的原版 Avalonia 窗口。请使用新的输出目录；探针使用其中的隔离数据，不替换用户的 ClassIsland 配置。

首次启动检查与热启停检查分别运行在两个真实 WPF 进程中，避免“先终止 Avalonia、再在同一进程重建平台”污染热启停结果。除原有启动、真实窗口渲染、插件安装与程序集隔离检查外，生命周期探针还会：

1. 通过 `ExtensionRuntime` 启用尚未打开 GUI 的插件，再停用，检查页面和托盘贡献移除，且未启动 Avalonia。
2. 连续八轮执行重新启用、托盘显示、原生窗口捕获、隐藏、打开设置、停用。每轮验证真实窗口像素、隐藏状态、旧窗口销毁和贡献移除。
3. 每轮停用后确认托管 `IHost` 已停止并释放；下一轮确认服务代次只增加一次、创建新的服务图，同时进程级 Avalonia 线程保持运行。
4. 修改隔离数据中的原版启动画面偏好，检查停用时保存、下一轮启动时读回。内嵌模式不显示启动画面，因此这个标记不影响窗口验证。
5. 导入及并发检查结束后执行最终停止，确认 Avalonia 线程结束、窗口销毁且内嵌应用引用释放。

探针使用真实插件管理器和 WPF 贡献协调器。在插件进入 Initialized、尚未 StartAsync 时，通过反射替换为使用隔离目录的宿主。后续启用、停用和卸载仍走生产代码路径。输出包括 `lifecycle.log`、`lifecycle-resources.csv`、每轮窗口 PNG 和最终 `result.txt`；任一检查失败则进程以非零状态退出。

CI 在框架依赖构建和 Windows x64 自包含发布中都运行该探针，单次进程总超时为 180 秒。

首次执行发现：停止第一个原版实例后，再启用会报 `Failed to create system events window thread`。SystemEvents 9 的窗口类名称仅包含 AppDomain 标识，每个插件私有加载上下文各自创建一份时会重复注册同名窗口类。修复将此依赖交由共享 WPF 契约程序集中的进程级提供器加载，保留与 WPF 自带旧版本的隔离，后续插件实例复用同一程序集。Windows 平台服务在停止时取消 TimeChanged 订阅；其他原版依赖仍按原方案隔离。回归另外断言各轮 SystemEvents 9 的程序集引用相同。

第二次 Windows 执行确认 SystemEvents 修复有效，第一轮重新启用完整渲染；第二轮重新初始化 Avalonia 时，ANGLE 的 EGL 窗口表面返回 `EGL_BAD_ALLOC`，窗口存在但捕获结果全透明。固定改用软件 Skia 后端后，第二轮仍出现透明窗口，确认问题是进程内重新初始化 Avalonia 平台，而不只是 ANGLE。只隐藏窗口虽然能保留渲染器，却会让通知、语音和音频等服务在插件停用后继续运行。

最终方案将两类生命周期分开：Avalonia Win32 平台、dispatcher 和渲染器在进程内保留一次；每次停用则等待完整托管 `IHost` 停止、释放服务提供器、保存设置并强制销毁所有会话窗口。重新启用在同一 Avalonia 平台上重建服务图和窗口，最终卸载才关闭平台线程。这样既不重复初始化 Avalonia，也不让后台服务越过禁用边界。原版 AXAML、控件、透明窗口、动画逻辑和优先渲染后端保持不变。

根因可对照 [.NET 9.0.7 SystemEvents 源码](https://github.com/dotnet/runtime/blob/v9.0.7/src/libraries/Microsoft.Win32.SystemEvents/src/Microsoft/Win32/SystemEvents.cs) 中的 `Initialize` 和 `EnsureSystemEvents`；本地并发测试加载同版本的 Windows 实现 DLL，仅检查加载身份，不在 Linux 上调用 Windows 事件 API。

这些是有限次数的生命周期回归，不代表长期运行内存、全部原版动画、DPI、通知和焦点行为已经验收。原版运行上下文目前不可回收；探针通过服务宿主状态检查停用边界，不以“窗口已关闭”推断所有服务或程序集内存已释放。任何启停或渲染策略调整仍需结合 Windows 结果和具体资源行为。

## PR91 后台任务与取消回归

停用时先通知应用停止，再卸载自动化工作流及触发器、取消在途动作并等待 Cron worker 结束，最后异步释放 DI 宿主。自动化停止后不再接受新动作；集合 Reset 也会卸载旧触发器。HangService 释放计时器并阻止迟到的检查重启。内置动作按名称补入插件已创建的菜单组，保留插件条目，重复构造不重复添加。

Windows 生命周期探针每轮使用真实服务创建 Cron 工作流，连续重载两次计划并启动一个 60 秒等待动作。确认任务正在执行后停用，等待超过卡顿计时器周期，再验证全部捕获的 Cron worker 已结束、动作停止、触发器卸载、设置事件退订，旧回调和设置变更不能重新启动任务。同时检查 ExactTimeService 计时器、进程级系统时间事件及窗口回调均已清理。菜单探针用插件预建的“运行”组连续构造两次 ActionService，验证插件条目与全部五个内置条目共存。

可移植运行时测试覆盖首次启动、挂起、恢复和最终停止部分执行后取消，要求终止清理并报告 Failed，下一次启用创建新实例；操作开始前已取消则保留原状态。即使 Stop 抛出异常也必须继续 Dispose。

“应用退出时”新触发的动作单独跟踪：普通动作取消，退出动作允许完成完整异步序列后再保存设置。探针用“等待 250 毫秒 → 修改启动画面偏好”验证后续动作确实执行。清理有 5 秒等待上限；超时或失败时再取消退出动作并最多等待 5 秒，随后报告停用失败，不能将未完成的停止报告为 Disabled。此上限不能强制终止第三方代码。

SettingsService 随会话释放，退订自动保存并拒绝释放后的显式保存；保存与释放互斥，防止旧天气等异步回调写回旧设置覆盖新会话。每轮探针在停用后修改旧设置并尝试显式保存，再读盘确认退出动作的结果未被覆盖。

本地验证包括宿主与原版 Windows 目标编译、可移植测试，以及真实 ActionService、HangService、CronTrigger 的服务级检查。当前 Linux 环境不能运行真实 Windows 窗口探针；它仍由 PR 的 Windows CI 在框架依赖构建和自包含发布中分别执行，验收以对应提交的结果为准。

## 导入与备份恢复

导入先在暂存目录复制并校验数据，再等待当前托管会话停止，随后替换数据。替换失败执行原有回滚；取消或回滚后也会重建先前会话。整个流程持有宿主操作互斥锁，恢复完成后才允许页面、托盘与插件启停继续操作。未启动过的插件只替换数据，下一次打开时加载。

恢复会话复用进程级 Avalonia 平台，重新读取磁盘配置并还原操作前的显隐状态。停止或恢复失败时终止运行时并报告错误；已生成的备份继续保留，用户可在备份列表中查找。恢复失败仍可能需要重启宿主。

Windows 生命周期探针在启停循环之后额外验证隐藏状态导入、可见状态恢复备份、服务代次变化、备份存在及恢复后的真实窗口像素，两种包体均执行。可移植测试验证异步停止完成前不替换数据，以及停止过程中取消后保留原数据并清理暂存目录。

最终释放也使用同一操作锁，等待导入和会话重建完成后再关闭 Avalonia。会话暂停及重建期间，主题回调只更新待应用值，恢复完成后应用最新主题。Windows 探针在原版 AppStopping 回调中暂停停止，期间触发主题更新与并发最终释放，验证主题回调及时返回、释放等待事务结束、最终 Avalonia 线程退出。


## P1 课堂设备基线

自包含发布包可直接运行长测。在解压后的包目录打开 PowerShell，指定一个新的输出目录：

```powershell
Start-Process .\ExusiAI.Desktop.exe -ArgumentList '--verify-classisland-soak', 'artifacts\classisland-soak' -Wait -PassThru
```

长测在一个 ExusiAI 进程内执行 24 轮启停。最后一轮分别保持显示和隐藏 2 分 30 秒，每 30 秒采样并检查原生窗口和宿主状态是否一致。退出码为 0 且生成 `result.txt` 表示通过。失败时查看 `failure.txt` 和保留的采样记录。

`lifecycle-resources.csv` 记录进程私有内存、工作集、线程、句柄、USER 和 GDI 对象数。启动耗时从发出启用指令计至确认信息岛可见，停用耗时计至插件运行时返回。对比预热后各轮的 `disabled` 样本可观察持续增长。结合 `resumed_hidden`、`visible`、`rendered`、`settings_open` 和 `suspended` 可缩小分配发生的阶段。CSV 采样包含整个测试进程的资源，且不会触发强制 GC。CI 分别上传框架依赖构建和自包含包的基线。

课堂设备验收还应单独记录以下结果：

- 在 Windows 10 和 11 上分别记录系统版本、显示缩放、显卡及驱动。
- 在双屏及不同 DPI 的环境切换主屏，检查信息岛位置、缩放、隐藏与再次显示。
- 打开设置或切回教学软件，检查焦点是否被信息岛抢占。确认隐藏与停用时通知、语音和托盘行为符合设置。

首轮 Windows CI 在两种包体上均观察到停用后的 GDI 对象从 28 增至 77。分段采样显示增长主要发生在重建会话和打开设置期间。资源计数以趋势记录，持续增长仍需进一步排查。

内嵌默认路径延迟创建原版托盘对象，并由 ExusiAI 提供托盘。每轮 Windows 探针检查 Avalonia Win32 的托盘注册表，确保常规启停和打开设置不会累积隐藏托盘注册。

信息岛跨会话复用原始 ICO，Avalonia 按窗口和 DPI 管理显示副本。FluentAvalonia 创建的标题栏原生源图标在替换或窗口关闭时释放。探针逐轮确认信息岛复用源图标，以及设置窗口关闭后其原生图标句柄归零。完成关闭和常规资源采样后，探针单独记录 `after_finalizers`，帮助区分尚未运行的终结器与仍被保留的资源。

顶层特效窗口由会话的服务容器释放。即使会话从未播放通知特效、窗口从未显示，停用时也会销毁其 HWND。探针另外在最后一轮启用高频置顶检查，验证关闭信息岛后定时器停止。
