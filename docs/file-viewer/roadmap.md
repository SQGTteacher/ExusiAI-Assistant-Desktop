# 文件查看器长期路线图

文件查看器以课堂可靠性、首次打开延迟、清晰度和宿主隔离为首要指标。它不是早期 Office 编辑套件替代品。任何格式只有在测试和兼容矩阵记录真实能力后，才会在 UI 中标记为支持。

## 阶段划分

1. **安全流式基础（当前）**：独立 Provider 契约与注册表；TXT/Markdown 增量读取；CSV 分页读取；取消、输入上限、UI 缓存上限、虚拟化；兼容矩阵和单元测试。
2. **Open XML 安全预览（进行中）**：阶段 2A+ 已在 DOCX 流式正文上识别标题、列表、段落和表格行；阶段 2B+ 已加入 XLSX 多工作表切换、当前工作表安全分页、共享字符串解析与公式缓存值只读显示；阶段 2C 已加入 PPTX 幻灯片顺序发现与结构化文本分页预览。后续继续补齐 DOCX 视觉层级、XLSX 基础日期/数字格式与 PPTX 可视渲染。ZIP 条目数、展开体积、压缩比和 XML 解析均设硬上限。
3. **课堂查看工作流（进行中）**：已加入 PPTX 随机跳转、有界 LRU 文本缓存、跨格式有界全文搜索、最近文件、邻页预热、拖放、Office 常用快捷键和 F5 全屏演示；UI 使用分层自适应命令栏、文档画布与可关闭搜索侧栏，PPTX 文本预览会将短首行作为标题并与正文分层显示，并提供每批 16 页的文本缩略导航，避免大演示文稿一次全部解析。后续集中推进高保真可视缩略图、释放/内存基准与更完整的后台索引。
4. **可选高保真适配器**：评估隔离进程中的 LibreOffice、本机 Office COM、WebView 或商业 SDK。每种适配器必须可缺失、可关闭、可超时和崩溃恢复；未经人工评审不合入。
5. **安全轻量编辑（已开始）**：TXT/Markdown 已启用编辑模式、保存/另存为、撤销/重做、剪切/复制/粘贴/全选与未保存更改保护；保存采用同目录临时文件、刷盘和原子替换，并尽量保留原始 BOM/文本编码。DOCX/XLSX/PPTX 在能够保证未知内容不被破坏前继续保持只读，后续按格式分别引入编辑事务与回滚策略。
6. **办公工作流（进行中）**：提供文档信息、路径复制、打开文件位置、最近记录清理、重新加载、磁盘外部更改冲突提示、自动换行、逻辑行跳转、文本统计、F3/Shift+F3 循环搜索结果、当前视图打印/系统 PDF 打印，以及 TXT/CSV 安全提取内容的流式原子导出；后续继续补齐页眉页脚、打印范围与更完整的无障碍键盘导航。

## Provider 边界

- `ExusiAI.FileViewer.Core` 只包含不依赖 WPF 的契约、安全预算和轻量 Provider。
- 每个复杂格式使用独立程序集/包；某个 Provider 缺失或初始化失败不得影响其他 Provider 或 Host。
- Provider 只解析数据；WPF renderer 负责虚拟化呈现；外部进程 adapter 必须位于独立边界。
- 默认不执行宏、脚本、OLE/嵌入对象或外部链接，不自动访问网络。

## 性能门槛（逐阶段建立基线）

每个受支持格式记录冷启动首次可见内容、首次可交互、内存峰值、连续滚动、切页、搜索 P50/P95 以及关闭后的资源释放。测试集至少覆盖 1 MiB、50 MiB 和接近配置上限的文件；具体阈值应依据目标教室设备实测后锁定，不能凭开发机数据承诺。
