# ClassIsland in ExusiAI

By default, enabling the plugin only registers its navigation and tray commands. Use an explicit show/settings/edit command to start ClassIsland on demand. The optional **随 ExusiAI 启动显示信息岛** setting opts into automatically showing the island next time ExusiAI activates the plugin; saving this choice does not open any windows.

Cold settings/profile startup initializes the island with an invisible, nonactivating native surface and hides it before reporting readiness. Settings can therefore open without flashing the information island. Show/hide commands retain the initialized runtime for subsequent use. The plugin page distinguishes a dormant runtime, a hidden running island, and a stopped runtime that requires restarting ExusiAI.

This plugin loads the original ClassIsland Avalonia desktop assembly from the bundled `NativeClassIsland` directory into the ExusiAI process. Its original information island, components, theme effects and settings are used directly. The ExusiAI page contains only controls to show or hide the original island and open the original settings. It has no alternate WPF renderer or imitation settings workbench.

The packaged SystemEvents 9 implementation is shared across plugin reloads through the host's WPF contract assembly. Its native broadcast window class is process-wide, so loading a separate copy on each activation would fail on the second startup. Other upstream dependencies retain their private runtime context; stopping unsubscribes the platform time-change bridge.

The original assemblies are built from the checked-in `third_party/ClassIsland` source during Debug and Release builds. No separate ClassIsland executable is packaged, started or downloaded. Native data is isolated in `%LocalAppData%\ExusiAI\ClassIsland`; the embedded application does not create a second tray icon. See `THIRD_PARTY_NOTICES.md` for upstream source and license details.

To reuse local ClassIsland courses and settings, choose **导入本机 ClassIsland 数据** and select the original `%AppData%\ClassIsland\Data` folder. Close any separately running ClassIsland first. The importer stages `Settings.json`, `Profiles` and `Config`, validates the settings JSON, then stops the embedded application before replacing its data. Existing data is kept in a timestamped `ClassIsland-before-import-*` folder beside the embedded data directory. Restart ExusiAI to load the imported data.

ClassIsland uses its independent upstream theme by default. Enable **跟随 ExusiAI 深浅色与强调色** on the plugin page to follow the shell. Disable it to immediately restore upstream settings. The choice persists separately from imported ClassIsland data; theme packs remain managed by ClassIsland.

The host page opens upstream course/profile editing, island component editing, and temporary lesson swapping through the original URI navigation handlers. Opening settings or the profile editor leaves a hidden island hidden; component editing and lesson swapping reveal it because those upstream flows use the island as their editing surface or dialog owner. Showing a previously initialized embedded window does not register its hooks and navigation handlers again.

When enabled, ClassIsland contributes a submenu to the existing ExusiAI tray icon: temporary lesson swapping, profile editing, component editing, upstream settings, and island show/hide. Disabling or uninstalling the plugin removes the contribution. No second tray icon is created.

All host page and tray commands share one operation gate. Import/restore cannot race a show/edit command or a host preference write. The page disables its controls together and offers cancellation for its own operation; tray cancellation is forwarded into native startup. Navigating away cancels the page operation. Copying checks cancellation between chunks; once replacement starts it finishes or rolls back before releasing the gate. Cancelling native initialization stops it and requires restarting ExusiAI.

The backup list shows saved import backups with settings. Select one and choose **恢复所选备份** to review the replacement prompt. Restore uses the same staging/validation/rollback path and first creates a new backup of the current data, allowing the restore to be undone. Startup/theme host preferences are retained. Backups do not contain installed plugin binaries or the entire upstream data tree.

The page subscribes to host state while loaded and unsubscribes when unloaded. Original Avalonia window visibility changes, runtime readiness/failure/exit, and operation completion notify it through the WPF dispatcher. Windows verification bypasses host commands to assert that native visibility changes emit a state notification. It also exercises dormant disable and three enable/render/disable cycles through the actual plugin manager, checking settings persistence, native window destruction and page/tray removal. See `docs/classisland/lifecycle-verification.md` in the source repository for coverage and limits. A stopped host instance still requires an ExusiAI restart; native runtime contexts are not collectible, so these bounded checks do not establish long-term resource reclamation.
